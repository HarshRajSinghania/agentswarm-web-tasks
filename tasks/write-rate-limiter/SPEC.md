# Limit client writes

Implement `createLimiter({perMinute, now})` returning `{tryTake(), msUntilNext()}`. This is a sliding-window limiter, explicitly chosen to satisfy at most 30 writes a minute; a conventional token bucket with capacity 30 would allow more than 30 writes in some rolling minutes. `perMinute` is a positive safe integer. `now` is a required injected function returning finite millisecond timestamps (fractional and negative are valid). Invalid options throw TypeError. Sample the clock on construction and exactly once on each method call. A non-number/nonfinite timestamp or backwards clock throws RangeError without changing history or last valid time. Clock exceptions propagate.

Initially up to perMinute immediate successful takes are allowed. At time t, discard successes at or before t-60000; only successful takes in (t-60000, t] count. `tryTake()` returns true and records t when capacity remains; otherwise false and records nothing. `msUntilNext()` returns 0 when a take would succeed; otherwise the positive integer ceiling of milliseconds until the oldest success expires. Querying does not consume capacity or reserve a slot. Independent limiter instances share no state. Neither method sleeps or schedules timers.

Node 22 standard library only; one self-contained `write_rate_limiter.mjs` with JSDoc types. No real clock, network, filesystem, processes or fixture access. Synthetic injected-clock traces are in fixtures/cases.json; exact boundary, fractional, invalid and rollback cases are also checked. Change only the implementation and optional IMPLEMENTATION.md. Development: `node tasks/write-rate-limiter/check.mjs --solution "$PWD/tasks/write-rate-limiter/write_rate_limiter.mjs"`; acceptance uses trusted pinned checks plus source/scope review.
